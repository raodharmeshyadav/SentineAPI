1. Executive Summary & Abstract

Modern web and mobile applications rely heavily on REST APIs for data transfer. However, while transport security (HTTPS) and basic token authentication (JWT) are routinely implemented, authorization logic flaws—most notably Broken Object-Level Authorization (BOLA/IDOR)—remain widespread.

SentinelAPI is an automated developer security tool designed to bridge the gap between rapid code deployment and security auditing. It ingests standard OpenAPI 3.0 / Swagger specifications, automatically builds test cases, and executes a Dual-Token Credential Matrix to deterministically verify whether one tenant's token can access or manipulate another tenant's confidential resources.

2. Problem Statement & Motivation

Traditional Dynamic Application Security Testing (DAST) tools like OWASP ZAP or generic vulnerability scanners evaluate syntactic payloads (e.g., SQL injection, XSS, and security headers). They fail to detect BOLA/IDOR because:

  • An unauthorized request targeting another user's ID is syntactically well-formed.
  • The API responds with HTTP 200 OK, leading traditional scanners to register a successful test.
  • Frameworks like FastAPI or Express lack built-in object ownership enforcement out-of-the-box, forcing developers to manually write if user.id != resource.owner: raise 403 on every route.

3. Methodology & System Architecture

SentinelAPI operates in four streamlined phases:

  • Specification Ingestion: Automatically parses the target API's OpenAPI specification, extracting all endpoints, HTTP methods, and path parameters (e.g., {id}, {patient_id}, {user_id}).
  • Dual-Token Credential Matrix (BOLA Detection): SentinelAPI provisions two authentic authenticated user identities (User A and User B). It requests User B's resource IDs using User A's token. If User B's private data is returned with status 200, BOLA is confirmed with 0% false positives.
  • Response Body Inspection (PII Exposure): Analyzes response JSON fields and regex patterns to identify unintended exposure of password hashes (bcrypt), Social Security Numbers, and internal live API secrets.
  • Remediation Generation: Provides reproducible cURL commands and concrete Python/FastAPI code patches to enforce authorization directly in the codebase.

6. Conclusion & Future Scope

SentinelAPI delivers a lightweight, developer-first solution to one of the most critical security vulnerabilities in modern software architecture. Future enhancements include:

  • A GitHub Actions CI/CD step that automatically runs SentinelAPI against PR preview environments and blocks merging if authorization checks fail.
  • Multi-step stateful workflow testing (e.g. testing privilege escalation through shopping cart checkout flows).
